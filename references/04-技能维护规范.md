## 2. 命名规则

- 文件名不带版本号；版本号手工出现在：SKILL.md frontmatter 的 version、SKILL.md 正文首行的“> 版本：”、references/00–08 各文件头部的“> 版本：”、README.md 的“> 版本：”、DEPENDENCIES.md 的“> 版本：”（共 12 处；check_structure.py 自动发现 references/*.md 后校验，不再硬编码文件名）；另一处生成物——docx 末尾的生成信息块，由 scripts/build_docx.py 从 SKILL.md 自动读取，不得写死。
- 版本号统一：同一版技能内上述各处版本号必须一致；生成物（工作区提示词、教学研究参考、教学资源取件手册）的版本号由 build_lesson_prompt.py 从 SKILL.md frontmatter 自动读取，禁止写死。
- 备份改用 git tag：每批开工前打 pre-v<版本>-<批次>（如 pre-v9.0.0-批三），发版打 v<版本>；不再往 references/历史版本/ 里放 .bak。2026-10-27 已把 180 个旧 .bak 移到工作区 .archived/教案-历史版本/（存一个月后删）。
- 工作区 教案生成要求提示词.md 是生成物，禁止手工修改；要改就改 00/01/02/06 后重新运行 build_lesson_prompt.py。
- references/联动判断清单.local.md 是 sync_checklist.py 的生成物，禁止手改；要改去改整理技能的 references/联动判断清单.md。
- 备份记在 git 里：pre-v<版本>-<批次> 与 v<版本> 两类 tag 就是备份，仓库不再存 .bak 副本。
- 课件素材命名：extract_enbx.py 的导出目录名已含课件名（含节号），目录内文件名保留 .enbx 原始资源名（GUID），清单表按原名登记；不逐文件加节号前缀。

## 3. 修改流程

0. **通用性检查**（改动任何条文前必做）：把准备写进技能的每条判据拿出来问三句——换个课时还成立吗？换个实验条件（仅多媒体／教师演示）还成立吗？是不是只能靠数字（几分钟、几行、几秒）才说得清？三句有一句不过，这条就降级为示例、或写成本节课的做法，不进通用规则；结论写进第 6 节变更记录。
1. 列清单：确定要改的文件。
2. 改权威源：直接在 /root/skill-repos/g9-physics 上改（工作区外，需一次放行）；覆盖前按第 2 节打 tag 备份。
3. 同步运行入口：权威源就是软链目标，无需复制；改完跑 skill_link.py verify 确认软链有效。

- 写文件前先问路，声明目的地的固定命令（新建不加 --update；更新已有文件加 --update；只有新增/改名产出文件才补规则与样本）：

      python3 ~/.dsh/skills/auto-organize-work-files/scripts/organize.py plan --name "<文件名>" --dest "<目标目录>" --workspace "/root/dsh-workspace/工作文件"
      python3 ~/.dsh/skills/auto-organize-work-files/scripts/organize.py plan --name "<文件名>" --dest "<目标目录>" --update --workspace "/root/dsh-workspace/工作文件"

- --update 表示声明的是更新已有文件；不加时目标已有同名文件会报「目标已存在同名文件」并退回规则判断（兜底 99-待处理/收件箱/）。

      python3 /root/.dsh/skills/auto-organize-work-files/scripts/organize.py lint --workspace "/root/dsh-workspace/工作文件"
